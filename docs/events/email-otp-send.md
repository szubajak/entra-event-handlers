# Email OTP Send

The `EmailOtpSend` event is raised by Microsoft Entra External ID when a one-time passcode (OTP) should be delivered to a user via email.

This event allows your application to:

- Use a custom email delivery provider
- Integrate with existing email infrastructure
- Apply custom branding and templates
- Track OTP delivery
- Route messages through enterprise messaging systems

Unlike most Entra events, `EmailOtpSend` supports a single response type: continue the flow after processing the email request.

---

## When is this event called?

Microsoft Entra invokes the `EmailOtpSend` custom authentication extension whenever an email verification code needs to be delivered to a user.

The request contains:

- The recipient email address
- The generated one-time code
- Authentication context information

Common use cases include:

- Sending OTPs through SendGrid
- Sending OTPs through Azure Communication Services
- Sending OTPs through Exchange Online
- Integrating with existing enterprise email platforms
- Applying custom email templates
- Tracking OTP delivery metrics

## Handler Base Class

Implement `EmailOtpSendHandlerBase` and override `HandleCoreAsync`.

```csharp
public class EmailOtpSendHandler(
    ILogger<EmailOtpSendHandler> logger)
    : EmailOtpSendHandlerBase(logger)
{
    protected override Task<EmailOtpSendResponse> HandleCoreAsync(
        EmailOtpSendEvent request,
        CancellationToken cancellationToken = default)
    {
        return Task.FromResult(
            EntraEventResponses
                .EmailOtpSend()
                .ContinueWithDefaultBehavior()
                .Build());
    }
}
```

The base class automatically provides:

- Request validation
- Structured logging
- Correlation ID logging
- Event name and event type logging scopes
- Execution duration measurement
- Exception handling
- Default response behavior when an unhandled exception occurs

## Available Responses

The `EmailOtpSend` event supports a single response action.

| Action | Purpose |
|----------|----------|
| ContinueWithDefaultBehavior | Continue the user journey after processing the OTP request |

---

## ContinueWithDefaultBehavior

Allows Microsoft Entra to continue the flow after your application processes the OTP delivery request.

### When to use

Always.

This is the only valid response for the `EmailOtpSend` event.

Your handler is responsible for sending the email before returning the response.

### Example

```csharp
public class EmailOtpSendHandler(
    ILogger<EmailOtpSendHandler> logger)
    : EmailOtpSendHandlerBase(logger)
{
    protected override Task<EmailOtpSendResponse> HandleCoreAsync(
        EmailOtpSendEvent request,
        CancellationToken cancellationToken = default)
    {
        return Task.FromResult(
            EntraEventResponses
                .EmailOtpSend()
                .ContinueWithDefaultBehavior()
                .Build());
    }
}
```

### Result

Microsoft Entra continues the verification flow.

## Real-World Example

A common implementation sends the OTP using a dedicated email service.

```csharp
public sealed class EmailOtpSendHandler(
    ILogger<EmailOtpSendHandler> logger,
    IEmailSender emailSender)
    : EmailOtpSendHandlerBase(logger)
{
    protected override async Task<EmailOtpSendResponse> HandleCoreAsync(
        EmailOtpSendEvent request,
        CancellationToken cancellationToken = default)
    {
        var otpContext = request.Data.OtpContext;

        var email = otpContext.Identifier;
        var code = otpContext.OneTimeCode;

        await emailSender.SendOtpAsync(
            email,
            code,
            cancellationToken);

        return EntraEventResponses
            .EmailOtpSend()
            .ContinueWithDefaultBehavior()
            .Build();
    }
}
```

In this example:

1. Microsoft Entra generates the OTP.
2. The handler receives the request.
3. The application sends the email.
4. The handler returns `ContinueWithDefaultBehavior`.
5. Microsoft Entra continues the user journey.

## Testing

Because email delivery logic lives inside the handler, it can be tested directly without hosting infrastructure.

Example:

```csharp
[Fact]
public async Task HandleAsync_SendsOtp_AndContinuesDefaultBehavior()
{
    var result = await handler.HandleAsync(request);

    await emailSender
        .Received(1)
        .SendOtpAsync(...);

    result.HasException.Should().BeFalse();
}
```

This allows validation of:

- OTP delivery logic
- Dependency interactions
- Generated responses
- Exception handling behavior

without:

- Running Azure Functions
- Running ASP.NET Core
- Creating HTTP requests

## Best Practices

### Send the Email Before Returning

Always complete email delivery before returning:

```csharp
await emailSender.SendOtpAsync(...);

return EntraEventResponses
    .EmailOtpSend()
    .ContinueWithDefaultBehavior()
    .Build();
```

---

### Keep Handlers Fast

The user is waiting for the verification process to continue.

Avoid:

- Slow database operations
- Long-running workflows
- Expensive computations

Prefer:

- Lightweight processing
- Reliable email providers
- Fast delivery paths

---

### Use a Dedicated Email Service

Good:

```csharp
IEmailSender
```

Avoid embedding email provider logic directly inside handlers.

This improves:

- Testability
- Maintainability
- Separation of concerns

---

### Log Delivery Failures

Track failed delivery attempts so operational issues can be diagnosed quickly.

Typical examples include:

- Provider outages
- Invalid email addresses
- Authentication failures
- Rate limiting

---

### Return Exactly One Action

Every `EmailOtpSend` response returns a single action.

Choose:

```csharp
.ContinueWithDefaultBehavior()
```

No other response actions are supported.

## Summary

The Microsoft Entra External ID `EmailOtpSend` event allows applications to take control of OTP email delivery while keeping the Microsoft Entra verification flow intact.

Supported responses:

| Response | Purpose |
|-----------|----------|
| ContinueWithDefaultBehavior | Continue the flow after processing the OTP request |

This event is commonly used for custom email providers, branded email templates, delivery tracking, enterprise messaging integration, and operational monitoring.
